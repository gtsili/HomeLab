🖥️ 1 · Compute Platform 4 decisions · AD-001 – AD-003 · AD-013
AD-001
ARM64 Nodes — Mac Mini
✓ Baseline
  • Hardware: 3× Apple Mac Mini (Apple Silicon — ARM64)
  • Roles: mm-cp = control plane + embedded etcd  ·  mm-w1, mm-w2 = ARM workers
  • Interconnect: Thunderbolt 4 mesh (40 Gb/s) — triangle topology where 2 TB ports exist per node
  • TB4 subnet: 192.168.100.0/24  ·  MTU 9000  ·  carries etcd heartbeat + pod overlay traffic
  • 10 GbE uplink to lab switch per node (VLAN 20 primary)
  • OS: Asahi Linux (ARM64 — full native, no emulation)
AD-002
Kubernetes — k3s Distribution
✓ Baseline
  • Distribution: k3s — lightweight, native ARM64 support, single binary
  • Control plane: k3s server with embedded etcd on mm-cp
  • Workers: k3s agent on all nodes (ARM + x86)
  • Runtime: containerd on every node
  • K8s API endpoint: 10.10.0.10:6443 (mm-cp) — fronted by HAProxy VIP
  • Pod CIDR: 10.42.0.0/16  ·  Service CIDR: 10.43.0.0/16 (k3s defaults)
  • Rationale: k3s chosen over full kubeadm for reduced resource footprint on Apple Silicon
AD-003
x86-64 Nodes — ESXi + Proxmox
✓ Baseline
  • VMware vSphere: 2× ESXi 8.x hosts managed by vCenter/VCSA
  • vSphere HA enabled  ·  DRS with anti-affinity rules  ·  vDS VLAN trunk (VLANs 10/20/30/40)
  • ESXi Host 1: mgmt 10.10.10.101  ·  storage NIC 10.10.30.101  ·  vMotion 10.10.40.101
  • ESXi Host 2: mgmt 10.10.10.102  ·  storage NIC 10.10.30.102
  • Proxmox VE: 3-node cluster (PVE 8.x, Corosync quorum, VLAN-aware bridge vmbr0)
  • Proxmox nodes: 10.10.10.111 – 10.10.10.113  ·  KVM VMs + LXC containers
  • Proxmox Backup Server (PBS) integrated for VM/CT snapshots
  • x86 K8s workers: x86-w1 (10.10.0.20) and x86-w2 (10.10.0.21) as k3s agents (amd64)
AD-013
Multi-arch Workload Scheduling
✓ Baseline
  • ARM nodes: labeled arch=arm64 — default scheduling target
  • x86 workers: tainted arch=amd64:NoSchedule — opt-in only
  • QEMU binfmt installed on all x86 workers — enables cross-arch image execution for testing
  • Image policy: multi-arch images (BuildKit buildx multi-node builder) are mandatory for all cluster-wide workloads (DaemonSets, system pods)
  • Single-arch images: must declare matching nodeSelector + toleration — no implicit placement permitted
  • CI/CD: multi-arch builds produced via GitHub Actions self-hosted runners (one ARM + one x86)
🌐 2 · Network Architecture 4 decisions · AD-004 · AD-005 · AD-006 · AD-012
AD-004
Core Networking — Mikrotik + Switch
✓ Baseline
  • Router: Mikrotik RouterOS (CCR/hEX) — gateway for all VLANs
  • WAN: ISP uplink with NAT/masquerade
  • Routing: inter-VLAN L3 routing  ·  OSPF/BGP for internal route distribution
  • Firewall: filter chains + mangle + NAT rules enforced at router
  • VPN: WireGuard site-to-cloud tunnel (Mikrotik native)  ·  static route for Tailscale CGNAT 100.64.0.0/10
  • Switch: 10 GbE managed switch — VLAN trunk to all nodes
  • MTU 9000 (jumbo frames) on switch  ·  LACP uplinks to router  ·  flow control ON  ·  EEE disabled (latency priority)
  • Port isolation enforced per VLAN — no intra-VLAN leakage
AD-005
VLAN & CIDR Design
✓ Baseline
  • VLAN 10 — Management  10.10.10.0/24  MTU 1500  ·  ESXi mgmt, vCenter, iDRAC/iLO, Mikrotik, Proxmox Web UI
  • VLAN 20 — VM LAN  10.10.20.0/24  MTU 1500  ·  General VMs, applications, K8s node IPs, services
  • VLAN 30 — Storage  10.10.30.0/24  MTU 9000  ·  iSCSI, NFS, MinIO — dedicated, no other traffic
  • VLAN 40 — vMotion/Migration  10.10.40.0/24  MTU 9000  ·  VMware vMotion, Proxmox live migration
  • VLAN 50 — DMZ  10.10.50.0/24  MTU 1500  ·  Internet-facing services, reverse proxy, Tailscale exit node
  • Thunderbolt mesh subnet: 192.168.100.0/24  ·  MTU 9000  ·  Mac Mini intra-ARM only
  • K8s Pod CIDR: 10.42.0.0/16  ·  K8s Service CIDR: 10.43.0.0/16  (k3s defaults)
  • Tailscale CGNAT: 100.64.0.0/10  ·  WireGuard overlay — remote access only
AD-006
Load Balancing & High Availability
✓ Baseline
  • Stack: HAProxy + Keepalived (VRRP) — active/standby pair
  • VIP: 10.10.20.100  ·  failover time: <1 second
  • L7 HTTPS: host-based routing — backends: Grafana, MinIO, Kibana, apps
  • L4 passthrough: K8s API port 6443 forwarded to mm-cp
  • TLS offload: internal CA certificate presented at VIP for all HTTPS backends
  • Health checks: per-backend active health probes
  • Stats/monitoring: :8404/stats endpoint (HAProxy native)
AD-012
Tailscale Overlay Network
✓ Baseline
  • Overlay: Tailscale WireGuard CGNAT 100.64.0.0/10 — remote access without public IPs
  • Subnet router: advertises 10.10.0.0/16 — all lab hosts reachable from tailnet without per-host agent
  • Mikrotik: static route 100.64.0.0/10 → subnet router (return path for lab-initiated traffic)
  • Exit node: lab internet egress on untrusted networks  ·  flag: --advertise-exit-node
  • ACL: default-deny policy  ·  group:admins → all:*  ·  group:readonly → metrics ports only
  • DNS: MagicDNS enabled  ·  split DNS resolves lab.local internally
  • K8s Operator: exposes selected K8s Services to tailnet (e.g. grafana-lab.ts.net, minio-lab.ts.net)
  • SSH: Tailscale SSH + SSH CA (step-ca) for zero-trust host access

AD-007
Storage Backends & Topology
✓ Baseline
  • All storage traffic isolated to VLAN 30 (10.10.30.0/24, MTU 9000) — no mixing with VM or management traffic
  • NFS — RHEL 8 server at 10.10.30.10  ·  NFSv4.1  ·  exports: /srv/nfs/vms (ESXi+PVE), /srv/nfs/k8s (PVCs), /srv/nfs/isos (read-only)
  • iSCSI — LIO/targetcli at 10.10.30.20:3260  ·  LVM thin pool backend  ·  MPIO 2-path per host  ·  shared VMFS datastores for ESXi HA
  • MinIO (S3) — at 10.10.30.30  ·  ports: API 9000, Console 9001  ·  TLS via internal CA
  • MinIO buckets: backups, artifacts, registry-cache
  • MinIO clients: mc, rclone, AWS CLI — used for DR replication to S3 (cloud)
  • Ceph (Proxmox-integrated) — NVMe OSDs on all 3 PVE nodes  ·  replicas: 2 (lab) / 3 (prod-grade)  ·  pools: vm-pool, k8s-pool
🔐 4 · Identity & Security 2 decisions · AD-008 · AD-009
AD-008
Identity & Authentication Chain
✓ Baseline
  • Architecture: three-tier federated identity chain — AD → FreeIPA → Keycloak SSO
  • Active Directory at 10.10.10.5 (Windows Server 2022)  ·  domain: lab.local  ·  authoritative DNS + LDAP 389/636 + Kerberos 88
  • FreeIPA at 10.10.10.6 (RHEL)  ·  LDAP + Kerberos + DNS  ·  cross-realm trust established with AD domain
  • FreeIPA provides: SSSD on all Linux hosts (PAM, SSH, sudo policy engine)  ·  Internal CA integration
  • Keycloak SSO at sso.lab.local  ·  backends (brokers): AD + FreeIPA via LDAP
  • Keycloak protocols: OIDC and SAML 2.0  ·  backend DB: PostgreSQL
  • Keycloak SSO clients: Grafana (OIDC), MinIO (OIDC), Kibana (SAML), vSphere, Proxmox, K8s API
AD-009
PKI & SSH Certificate Authority
✓ Baseline
  • PKI: step-ca at ca.lab.local (10.10.20.81) — two-tier hierarchy: Root CA → Intermediate CA
  • ACME provisioner: automatic TLS certificate issuance + renewal (90-day lifetime)
  • TLS consumers: Keycloak, MinIO, Grafana, Kibana, HAProxy — all present internal CA certificates
  • CRL and OCSP endpoints published for certificate status checks
  • SSH CA: step-ca issues host certificates + user certificates (replaces static authorized_keys)
  • Trust distribution: Ansible playbook pushes root CA cert to all hosts' trust stores on provisioning

⚙️ 6 · Operations & Integration 2 decisions · AD-014 · AD-015
AD-014
Cloud & Hybrid Integration
✓ Baseline
  • Cloud burst compute: AWS/Azure/GCP VMs joined to tailnet — used for CI/CD runners and native amd64 multi-arch builds
  • Disaster recovery replication:
  • MinIO → S3 (cloud): rclone scheduled sync via Tailscale/WireGuard tunnel (offsite backup)
  • MariaDB → Cloud RDS: DR replica for relational data
  • Elasticsearch CCR (cross-cluster replication) → cloud ES cluster
  • Site-to-cloud VPN: WireGuard tunnel configured natively on Mikrotik router
  • Legacy interop bridge layer:
  • Samba: CIFS file shares with AD authentication (Windows client compatibility)
  • nginx auth_request: retrofits Keycloak SSO onto legacy HTTP applications
  • FreeRADIUS: replaces Cisco ACS — 802.1X / RADIUS for network device authentication
  • Logstash SNMP input: polls legacy devices (no syslog support) → ELK pipeline
AD-015
Automation & Change Control Policy
✓ Baseline
  • Ansible: all provisioning and configuration procedures are Ansible playbooks — idempotent, no manual snowflake changes permitted
  • GitOps: Flux or ArgoCD manages all k8s workload state — no kubectl apply from local machines
  • CI/CD pipeline: GitHub Actions with self-hosted runners (1× ARM + 1× x86) — multi-arch image builds on every push
  • Change log: every change recorded with timestamp, operator ID, pre-change snapshot, post-change snapshot, and metric export
  • No snowflakes: node state is code — any undocumented manual change is a policy violation
  • Blueprint maintenance (mandatory): lab_architecture.html and all persistent lab documents updated on every architectural decision — no exceptions
